# Resvera v0.2.0

First release where models can be installed from inside the app.

## Models are now downloadable

`v0.1.0` shipped a Model Center that could only import a package you already had.
The signed catalog pointed at no artifacts, so the Download button was
deliberately hidden rather than offering a download guaranteed to fail.

Both validated packages are now published as signed release assets
([`models-v1`](https://github.com/BerryUIKI/resvera/releases/tag/models-v1)) and
wired into the catalog:

| Model | Family | Size | SHA-256 |
|---|---|---|---|
| Real-ESRGAN x4plus | RRDB | 67,051,643 B | `1d276713…` |
| Real-ESRGAN x4plus Anime (6B) | RRDB-6B | 17,939,968 B | `f5beb1f1…` |

Downloads are verified twice before anything is activated: the SHA-256 must match
the catalog entry, and the catalog's Ed25519 signature must verify against the
pinned trust root. A failure leaves the previously installed version intact.

## 8x upscaling

Requests above a model's native scale now run a cascade: two passes at the
model's own scale, then a Lanczos3 downsample to the requested size. A 4x model
serves 8x this way.

This is bounded by memory, not compute. The peak working buffer is the *last
pass* output — 16x for an 8x request — so only small inputs qualify. The limit is
checked at submit time and reported as a structured error rather than failing
mid-job. The UI states this when 8x is selected.

## Correctness work behind the release

Most of the work in this cycle was making claims checkable rather than adding
surface area:

- **Parity is measured against a float64 reference.** The suite used to compare
  two float32 implementations and treat one as truth; on the `gradient` fixture
  the backend treated as ground truth was ~4.6x less accurate than the one being
  judged. Thresholds were not relaxed.
- **Catalog digests are reproducible.** Both were re-exported with the pinned
  toolchain (`torch 2.4.1` / `onnx 1.16.2`) and can be regenerated from the
  upstream checkpoints. CI verifies every pinned digest is backed by committed
  evidence.
- **The catalog trust root was rotated.** The previous seed had been committed in
  plaintext in the test suite, so signatures proved integrity against corruption,
  not authenticity.
- **Dependency advisories cleared.** Frontend 23 → 0; Rust now includes a working
  audit gate that had been failing on every push without running.
- **Model Center no longer advertises accelerators it cannot run.** Provider
  claims are restricted to CPU, matching what the engine actually executes.

## Known limitations

- **Execution is CPU-only.** DirectML, CoreML and CUDA are architecturally
  integrated but fail closed to CPU pending hardware parity reports.
- **Real-CUGAN and Real-HAT-GAN are not shipped.** The adapters exist in the
  core library, but neither has a validated package, so neither appears in the
  catalog.
- **8x requires a small input** — see above. There is no streaming cascade yet.
- **Real-CUGAN / HAT adapter work** is tracked separately and is unaffected by
  this release.

## Upgrade notes

The model catalog trust root and the updater signing key both changed in this
cycle. Builds older than this release verify the catalog against the previous
root and will reject the new catalog; update to v0.2.0 rather than mixing.
